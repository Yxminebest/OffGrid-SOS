## ข้อสรุป

อยู่ในขั้นต้นแบบที่พร้อมเริ่มทดสอบภาคปฏิบัติแบบควบคุมด้วย Android สองเครื่อง
มีโค้ด UI, บัญชี, SOS ในเครื่อง, คิวซิงก์ และ Nearby แล้ว
ยังไม่มีผลทดสอบรับส่งจริงสองเครื่องในรอบตรวจนี้ และยังไม่ควรนับว่าระบบฉุกเฉินพร้อมใช้งานจริง
ไม่กำหนดเปอร์เซ็นต์ความสำเร็จ เพราะการมีโค้ดกับการผ่านทดสอบบนโทรศัพท์เป็นหลักฐานคนละส่วน

## เครื่องและ APK

- เครื่อง A: Galaxy ที่ผู้ใช้เคยติดตั้ง ในประวัติการเชื่อมต่อเป็น Galaxy A03s
- เครื่อง B: vivo Y33s ตามที่ผู้ใช้ยืนยัน

- ขนาด 58,351,805 bytes; รองรับ Android API 24 ขึ้นไป (Android 7.0 ขึ้นไป)
- มี ARM 32-bit, ARM 64-bit และ x86_64; ตรวจลายเซ็น APK ผ่าน
- เป็น Release build แต่ยังลงนามด้วย debug key ตาม Gradle ไม่ใช่กุญแจสำหรับเผยแพร่จริง
- ไม่พบบันทึกแก้ไฟล์ `lib` หลังเวลา APK รุ่นนี้ถูกสร้างจากการตรวจ timestamp แต่ timestamp ไม่ใช่หลักฐานแทนการทดสอบบนเครื่อง

## ประเด็นที่พบจากโค้ด

### 1. การยกเลิก SOS ตอนหลุดไม่ถูกส่งซ้ำเมื่อเชื่อมใหม่ — ควรแก้ก่อนทดสอบความทนทาน

ที่ `lib/services/nearby_mesh_service.dart` ฟังก์ชัน `stopSos` ล้าง `mySos` แล้วส่ง
`active: false` เพียงครั้งเดียว หากไม่มีการเชื่อมต่อ `_broadcast` จะส่งได้ 0 เครื่อง
เมื่อเชื่อมต่อใหม่ `_result` ประกาศเฉพาะ `mySos` ที่ยังมีอยู่ ไม่มีคิวสถานะยกเลิก
เครื่องกู้ภัยที่เคยได้รับเคสเดิมอาจยังเห็นว่า active อยู่

วิธียืนยัน: A ส่ง SOS ให้ B → ทำให้หลุด → A หยุด SOS → เชื่อมใหม่ → ดูว่าเคสเดิมหายจาก B หรือไม่
ผลตามโค้ดปัจจุบันอาจค้าง ต้องเก็บสถานะยกเลิก/เลข revision และส่งซ้ำหรือ reconcile เมื่อเชื่อมใหม่

### 2. แชทตามเคสกรองผู้รับที่ UI แต่ส่งข้อมูลไปทุก peer

`sendCaseReply` ส่ง `target` ใน JSON แต่ `_broadcast` ส่งซองนั้นให้ทุกอุปกรณ์ที่เชื่อมต่อ
และ `_received` ส่งต่อซองได้ ส่วนหน้าจอแชทกรองเฉพาะคู่สนทนา
นี่ไม่ใช่หลักประกันว่าข้อมูลเป็นความลับจากอุปกรณ์ตัวกลาง
ต้องแยกการยืนยันตัวตนผู้ส่ง/สิทธิ์และการเข้ารหัสแยกผู้รับที่ระดับแอปก่อนใช้กับข้อมูลจริง
การตรวจนี้ไม่ได้อ้างว่า transport ของ Nearby ไม่มีการเข้ารหัส

### 3. ช่องรหัสผ่านก่อนลบบัญชีไม่ได้ถูกนำไปตรวจใน service

`AuthService.deleteMyAccount(currentPassword: ...)` รับรหัสผ่าน แต่ไม่ได้เรียกตรวจรหัสผ่าน
และส่งไป Edge Function เพียง `confirm: true` หน้าจอตรวจเพียงว่ากรอกไม่ว่าง
จึงไม่ควรแสดงว่าฝั่งแอปตรวจรหัสผ่านปัจจุบันแล้ว
ยังไม่มีซอร์ส `delete-account` ใน repository นี้ให้ยืนยันเงื่อนไขฝั่งเซิร์ฟเวอร์

### ข้อจำกัดอื่นที่มีอยู่จริง

- Inbox Nearby อยู่ใน RAM จำกัด 150 ซอง และไม่เก็บแชทถาวร ปิดโปรเซสแล้วข้อความที่รับมาหาย
- `_seen` ไม่จำกัดจำนวนตลอด session; ควรใช้ cache ที่มีอายุ/ขนาดจำกัดก่อนใช้งานยาวนาน
- `sendBytesPayload` สำเร็จยังไม่มีข้อความตอบรับระดับแอปว่าอีกฝ่ายอ่าน/บันทึกแล้ว
- ไม่มี foreground service/ระบบแจ้งเตือนที่รับประกันการรับเมื่อจอดับหรือแอปถูกปิด
- สถานะเคสฝั่งผู้รับเลือกตามลำดับซองที่มาถึง ยังไม่มี revision สำหรับแก้ปัญหาข้อมูลเก่ามาถึงทีหลัง
- ทดสอบ mesh หลายทอดต้องมีอย่างน้อย 3 เครื่อง สองเครื่องพิสูจน์ได้เฉพาะการเชื่อมตรง
- แผนที่เปิดผ่านแอปภายนอก ไม่ได้มีชุดแผนที่ออฟไลน์ภายใน Offgrid SOS
- ยังไม่พบ SQL migrations/นิยาม RLS/RPC/Edge Function ใน repository จึงยังตรวจสิทธิ์ backend ครบวงจรไม่ได้
- ยังมีไฟล์ที่แก้/เพิ่มจำนวนมากไม่ได้ commit ควรบันทึกเวอร์ชันที่ทดสอบเมื่อผลทดสอบนิ่งแล้ว

## ชุดหน่วยกู้ภัยและแชทกลับ

ต้องมีบัญชีได้รับอนุมัติแล้ว ซึ่งผู้ใช้ยังไม่ได้ยืนยันว่ามีหรือไม่
Guest ใช้ทดสอบฟีด SOS ได้ แต่เข้าโหมดหน่วยกู้ภัยไม่ได้ตามเงื่อนไขโค้ด

1. ต่ออินเทอร์เน็ตและเข้าสู่ระบบบัญชี `rescuer`/`admin` บน B ก่อน
2. A ใช้ Guest; B ไปหน่วยกู้ภัย → เริ่มปฏิบัติหน้าที่
3. จับคู่ Nearby และยืนยันรหัสทั้งคู่ จากนั้นตัดอินเทอร์เน็ตโดยเปิด Wi-Fi/Bluetooth ค้างไว้
4. A ส่ง SOS; B ต้องเห็นเคสพร้อมข้อความ/พิกัดและเวลาพิกัด
5. B เปิดเคส → แชทกับผู้แจ้ง SOS → ส่งข้อความทดสอบ
6. A เปิด SOS → แชทกับหน่วยกู้ภัยผ่าน Nearby → ตอบกลับ
7. A หยุด SOS ขณะเชื่อมต่อ; เคสต้องหายจากรายการ active ของ B

ถ้ายังไม่มีบัญชีกู้ภัย ให้ใช้กระบวนการส่งคำขอยืนยันและ Admin อนุมัติที่มีอยู่
ไม่เปลี่ยน role ใน APK เพื่อทำให้ผลทดสอบดูผ่าน

## ชุดสมาชิกและ Supabase ภายหลัง

ทดสอบด้วยสมาชิกสองบัญชีต่างกัน: ค้นหาเพื่อน/สร้างห้อง/ข้อความ/รูป/พิกัด/แก้/ลบ/อ่านแล้ว
สร้างห้องขณะออนไลน์ก่อน แล้วตัดอินเทอร์เน็ต ส่งข้อความในห้องเดิม เปิดเน็ตและตรวจส่งถึงอีกบัญชี
ตรวจ bucket `avatars`, `chat-media`, `rescue-verification`, Realtime และ RLS ด้วยบัญชีที่เกี่ยวข้อง
รวมถึง RPC ที่เรียกจาก `ChatService`/`AuthService` และ Edge Function `delete-account`
