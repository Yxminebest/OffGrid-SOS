# Demo 7–10 นาที

เป้าหมาย 9 นาที ใช้ APK รุ่นเดียวกันทั้ง 2 เครื่อง และเครื่องที่สามสำหรับหลายทอด
เตรียมบัญชี user/rescuer ที่อนุมัติแล้ว รูปหนึ่งภาพ วิดีโอสั้น และเปิดสิทธิ์ให้ครบก่อนเริ่ม

| เวลา | สาธิต | สิ่งที่ผู้ชมต้องเห็น |
|---|---|---|
| 0:00–0:45 | ปัญหาและผู้ใช้เป้าหมาย | เครือข่ายล่ม แต่ใช้วิทยุในโทรศัพท์ส่งข้อมูลได้ |
| 0:45–1:30 | สมาชิก/Guest และสว่าง–มืด | บัญชี cloud กับประวัติ local แยกเจ้าของ |
| 1:30–2:30 | ปิด mobile data/ไม่ต่อ hotspot จับคู่ A/B | ไม่ต้องอาศัย infrastructure; ยืนยันรหัสตรงกัน |
| 2:30–4:00 | แชท ข้อความ กล้อง รูป วิดีโอ | รับถึงเครื่อง เปิดสื่อออฟไลน์ได้ |
| 4:00–5:00 | เปิด SOS และกดฝั่งรับ | แดง เข้าแชท และดู/คัดลอกพิกัด; ปิดแล้วถอนสถานะ |
| 5:00–5:45 | เปิด/ปิด Rescue | น้ำเงินเฉพาะโหมดทำงานและบนอีกเครื่อง |
| 5:45–7:00 | A↔B↔C หลายทอด และตัด B | C รับข้อความ/สื่อผ่าน B; ค้างส่งเมื่อเส้นทางหาย |
| 7:00–8:15 | เปิด Internet ซิงก์ Nearby | สถานะรับถึงกับสำรองแยกกัน; ดูข้อมูลใน private archive |
| 8:15–9:00 | แจ้งเตือน/ทดสอบ/ข้อจำกัด | กด Home ฝั่งรับ, แสดงผลทดสอบและลิงก์ README/GitHub/APK |

ถ้ายังไม่มีเครื่องที่สาม ให้แสดงผล automated 3-node พร้อมระบุว่าเป็นจำลอง
ห้ามนำการคุย 2 เครื่องไปอ้างเป็นหลักฐาน multi-hop จริง

สิ่งที่ส่ง: GitHub source ที่ push รุ่นล่าสุดแล้ว, APK, README, UX/design,
backend setup/schema, test results/bug log และคลิปหรือ demo สด
ยังต้อง push source และบันทึกผลฮาร์ดแวร์จริงก่อนส่งงาน
