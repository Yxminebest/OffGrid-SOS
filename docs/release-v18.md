# 0.8.0+18 — เตรียมรุ่นพร้อมทดสอบและส่งมอบ

วันที่ 24 ตุลาคม 2569 ผู้ใช้ขอพักการทดสอบและการติดตั้งบนโทรศัพท์

## เพิ่มจากรุ่น 17

- Supabase ออกใบรับรอง Ed25519 ผูกบัญชี/บทบาทกับ device ID และกุญแจ X25519/Ed25519 ของโทรศัพท์
- ฝั่งเซิร์ฟเวอร์ตรวจ JWT ด้วย Auth, ตรวจ session ที่ยังอยู่ใน auth.sessions และอ่านสิทธิ์จาก user_roles ไม่ใช้ user_metadata
- คีย์ลงลายเซ็นสร้างใน PostgreSQL และอยู่ใน private.mesh_issuer_keys ไม่ถูกอ่านมาใส่ในโค้ด APK หรือเอกสาร มีเฉพาะ service-role RPC ที่เข้าถึงได้
- APK ฝัง public key ของโปรเจกต์นี้ ไม่เชื่อกุญแจที่ส่งมาจากคู่เชื่อมต่อ ไม่เปลี่ยน trust anchor อัตโนมัติ
- ตรวจใบรับรองได้ออฟไลน์ อายุสูงสุด 30 วัน ต่ออายุเบื้องหลังเมื่อออนไลน์ทุก 6 ชั่วโมงหรือเมื่อสิทธิ์เปลี่ยน หากไม่มีใบรับรอง/หมดอายุยังส่ง SOS และแชทใกล้เคียงได้ แต่เปิดสถานะกู้ภัยที่ยืนยันแล้วไม่ได้
- ก่อนรวมบัญชีคลาวด์กับผู้ติดต่อวิทยุ ต้องตอบ nonce challenge ผ่านช่องทางเข้ารหัสเพื่อพิสูจน์ว่าครอบครอง private key การคัดลอกใบรับรองสาธารณะอย่างเดียวไม่พอ
- hello ใช้ค้นหาอุปกรณ์ ไม่ใช่หลักฐานบัญชี; contact binding รุ่นเก่าที่ไม่มีใบรับรองถูกลดเป็นผู้ติดต่อแบบ device โดยยังคงประวัติไว้
- เข้ารหัส payload ส่วนตัวและ ACK ทั้งลิงก์ตรงและหลายทอดด้วย X25519/AES-GCM ปฏิเสธ private frame ที่มาแบบ plaintext
- ลงลายเซ็น SOS/Rescue ก่อนส่งหรือส่งต่อ ตรวจต้นทางก่อนบันทึก โดย TTL เปลี่ยนได้ระหว่าง relay แต่เนื้อหา/ต้นทางเปลี่ยนไม่ได้
- เก็บ revision ของการเปิด/ปิดกู้ภัยลง local DB เพื่อไม่ให้ replay สถานะเก่าทับสถานะปิดที่เคยรับแล้ว หลังเริ่มแอปใหม่
- ผู้ประกาศกู้ภัยที่ยังไม่ตรวจใบรับรองจะแสดงเป็นประกาศรอจับคู่ สีฟ้า/น้ำเงินที่ยืนยันแล้วใช้หลังตรวจหลักฐานสำเร็จ
- ดาวน์โหลดสื่อ cloud ล่าสุดแบบทีละไฟล์เบื้องหลังเมื่อออนไลน์ สูงสุด 10 รายการล่าสุดที่เข้าเงื่อนไขจาก 200 ข้อความล่าสุด ไฟล์ไม่เกิน 25 MB ข้อความ/SOS ไม่ต้องรอการดาวน์โหลด
- ไฟล์ที่ดาวน์โหลดเสร็จอยู่ใน account-scoped durable cache; ไฟล์ที่ยังไม่ครบไม่ถูกแสดงว่าใช้ได้ออฟไลน์ งานหยุดเมื่อเปลี่ยนบัญชี และลองใหม่หลังเครือข่ายกลับมา

## Backend ที่ติดตั้งแล้ว

1. `20261024052517_mesh_server_attestation.sql`
2. `20261024053004_mesh_attestation_session_gate.sql`
3. Edge Function `mesh-attestation` version 2

GET ของ function ส่งเฉพาะ public verification key ส่วน POST ต้องมี user JWT ที่ Auth ยอมรับ พร้อม session ที่ยังใช้ได้และ proof-of-possession ของกุญแจอุปกรณ์
ตั้ง platform verify_jwt=false เพราะ GET เป็นข้อมูล public; POST ตรวจ user token ภายใน function เสมอ ไม่ใช่ endpoint ออกใบรับรองแบบ anonymous
dependencies ของ function ตรึง `@supabase/supabase-js@2.118.0` และ `tweetnacl@1.0.3`

ตรวจ metadata หลัง migration: anon/authenticated เรียก RPC อ่าน issuer seed ไม่ได้, service_role เรียกได้, สมาชิกอ่านตาราง private ไม่ได้, เปิด RLS แล้ว
Security advisor มี INFO ว่าตาราง private เปิด RLS ไม่มี policy ซึ่งตั้งใจให้ default-deny และมี WARN เดิมเรื่อง leaked password protection

## ก่อนเริ่มใช้เมื่อกลับมาทดสอบ

อัปเดตทุกเครื่องเป็นรุ่น 18 เพราะมีการบังคับลายเซ็นสถานะและเข้ารหัสลิงก์ตรง รุ่นเก่าไม่รองรับ protocol นี้ครบ
สำหรับสมาชิก/กู้ภัย เปิดแอปออนไลน์หนึ่งครั้งเพื่อรับใบรับรองของเครื่องนั้นก่อนปิดเน็ต อนุมัติ role ของบัญชีแล้วต้องให้แต่ละเครื่องรับใบรับรองใหม่ด้วย
Guest เริ่มใช้งานแชทและ SOS ออฟไลน์ได้โดยไม่ต้องมีใบรับรองบัญชี
ตั้งวันที่/เวลาของโทรศัพท์ให้ถูกต้อง เพราะมีผลต่ออายุใบรับรองและพิกัด

การถอนสิทธิ์จากเซิร์ฟเวอร์ไม่สามารถส่งไปเครื่องที่ตัดขาดอินเทอร์เน็ตได้ทันที ใบรับรองที่เคยออกยังมีอายุได้จนถึงวันหมดอายุ การต่ออายุจะใช้สิทธิ์ปัจจุบัน
GPS/วิทยุ/แบตเตอรี่/พื้นที่จัดเก็บและการที่ระบบสั่ง force-stop ยังเป็นข้อจำกัดจริง แผนที่ออฟไลน์ครอบคลุมปทุมธานีตามที่กำหนด

## การตั้งค่าที่ต้องทำผ่านบัญชี Dashboard

ยังไม่เปิด Leaked Password Protection: connector ไม่มีคำสั่งแก้ Auth config, IAB ไม่ได้ล็อกอิน และ Chrome ไม่เชื่อมต่อกับเครื่องมือรอบนี้ แม้ได้รับอนุญาตจากผู้ใช้แล้ว
