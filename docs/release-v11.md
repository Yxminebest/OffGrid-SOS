## จุดที่พบและแก้

1. การกู้คืนบัญชีเดิมเคยรอ HTTP ก่อนอ่านแคช เปลี่ยนเป็นอ่านตัวตนในเครื่องก่อน ใช้ D2D ต่อได้แม้ session คลาวด์หมดอายุ โดยยังไม่ให้สิทธิ์เรียกคลาวด์จากแคช หากมี session เป็นคนละบัญชีจะไม่เอาประวัติเก่าไปผูกให้บัญชีใหม่
2. แยกการคืนการทำงานของวิทยุและการกู้คืนรูปกล้องออกจากการเริ่มบริการคลาวด์ จึงไม่รอการตรวจอินเทอร์เน็ต/ซิงก์ก่อนเริ่มงานในเครื่อง
3. จดจำโหมด Nearby หรือ Bluetooth ที่เปิดสำเร็จ แยกตามบัญชี เมื่อเปิดแอปใหม่จะเริ่มโหมดเดิม หากผู้ใช้กดหยุดเองจะไม่เริ่มใหม่อัตโนมัติ ไม่รับรองว่าคู่เชื่อมต่อจะกลับมาทันที: Nearby อาจต้องยืนยันการจับคู่ใหม่ และ Bluetooth อาจต้องเลือกเครื่องที่เคยจับคู่
4. เมื่อเปิด SOS จะบันทึกในเครื่องและเริ่มโหมดวิทยุที่เลือกไว้ ถ้ายังไม่เคยเลือกจะลองเริ่ม Nearby การส่ง/แก้ไข/หยุด SOS ไม่รออัปโหลดคลาวด์ และข้อมูลในคิวยังอยู่ถ้าเครือข่ายล่ม
5. คำขอจับคู่หลายเครื่องพร้อมกันเคยเขียนทับ pendingPeer ทำให้เครื่องกลางรับคำขอได้ไม่ครบ เปลี่ยนเป็นคิวแยกชื่อและรหัสยืนยันตามเครื่อง ไม่อนุมัติอัตโนมัติ
6. ป้องกัน callback Bluetooth เก่าหลังหยุด/เปลี่ยน session รวมถึงการกดหยุดขณะรอสิทธิ์หรือรอ native start ไม่ให้ผลตอบกลับล่าช้ากลับมาเปิดสถานะเชื่อมต่อเอง
7. เพิ่มหน้า “ระยะและทิศทางออฟไลน์” จากไอคอนเข็มทิศในหน้าแผนที่ หรือปุ่มเมื่อโหลดภาพถนนไม่ได้ ใช้ GPS + พิกัดที่บันทึกไว้คำนวณในเครื่อง ไม่มีการเรียก tile server ในหน้านี้

## ขอบเขตที่ทำงานโดยไม่ใช้อินเทอร์เน็ต

- Guest เริ่มใช้ได้ตั้งแต่ครั้งแรกโดยไม่สมัครบัญชี สมาชิกเดิมเข้าใช้จากตัวตนที่บันทึกไว้ได้
- ข้อความ รูป วิดีโอ ภาพจากกล้อง ตำแหน่ง SOS และโหมดกู้ภัยที่เคยได้รับสิทธิ์แล้ว ใช้การเชื่อมต่อระหว่างอุปกรณ์
- ประวัติ/ไฟล์และคิวข้อความอยู่ในเครื่อง แสดงค้างส่ง ส่งแล้ว และยืนยันรับถึงเครื่องแยกจากสถานะสำรองคลาวด์
- เส้นทาง A–B–C ใช้เครื่อง B ส่งต่อแบบเข้ารหัส ข้อความส่วนตัวและไฟล์ไม่ปรากฏในประวัติแชทของ B
- เมื่อเส้นทางขาด คิวอยู่ที่ผู้ส่ง เมื่อเส้นทางกลับมาจะลองใหม่และรับ ACK โดยไม่เพิ่มข้อความซ้ำ
- แจ้งเตือนในเครื่องได้โดยไม่ใช้เซิร์ฟเวอร์ เมื่อแอป/บริการที่ประมวลผลยังทำงานและอนุญาตการแจ้งเตือน

## เงื่อนไขและสิ่งที่ยังต้องพิสูจน์

ไม่มีอินเทอร์เน็ต ≠ ปิดวิทยุทุกชนิด ต้องเปิด Bluetooth หรือวิทยุ Wi-Fi ที่ใช้ D2D ไม่ต้องต่อ hotspot/router หากปิดวิทยุ Wi-Fi ให้ใช้ “Bluetooth โดยตรง” และจับคู่ผ่านการตั้งค่า Android ก่อน

อุปกรณ์ต้องอยู่ในระยะและมีเส้นทางต่อกัน เครื่องกลางต้องเปิดแอป/บริการและเชื่อมต่อสองฝั่ง การหลุดของ B ทำให้ A ส่งถึง C ไม่ได้ในขณะนั้น; คิวรอที่ A ไม่ใช่ระบบให้ B ถือข้อความไปส่งภายหลังเมื่อผู้ส่งหายไปแล้ว (DTN)

เมื่อ Android force-stop แอป รีบูต หรือปิดกระบวนการ ต้องเปิดแอปอีกครั้ง บริการ foreground ไม่รับประกันว่าจะรอดการปิดกระบวนการ/ข้อจำกัดแบตเตอรี่ทุกยี่ห้อ

ภาพถนนยังต้องมีอินเทอร์เน็ตหรือแคชที่โหลดไว้ ส่วนพิกัด ระยะเส้นตรง และทิศทางคำนวณออฟไลน์ได้ ลูกศรอ้างอิงทิศเหนือด้านบนหน้าจอ ไม่ใช่เข็มทิศตามการหมุนเครื่องหรือเส้นทางเดินจริง GPS ต้องได้รับสิทธิ์และหาตำแหน่งได้ กรณีไม่มีพิกัดใหม่จะแสดงข้อมูลล่าสุดพร้อมคำเตือน หรือระบุว่าหาตำแหน่งไม่ได้

สมัครสมาชิกใหม่ ยืนยันอีเมล อนุมัติสิทธิ์ใหม่ และสำรอง/กู้คืนคลาวด์ต้องมีอินเทอร์เน็ต การกู้คืนตัวตนในเครื่องไม่สร้าง session คลาวด์ใหม่; เมื่อ session ใช้ไม่ได้ต้องเข้าสู่ระบบออนไลน์ใหม่เพื่อใช้บริการคลาวด์
