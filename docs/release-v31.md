# รุ่น 0.10.0+31 — ยืนยัน SOS และรับเคสออฟไลน์

2 พฤศจิกายน 2569

## สิ่งที่แก้และเพิ่ม

1. หลังปลายทางบันทึก SOS ลง local DB จะส่ง encrypted receipt กลับต้นทางผ่าน Bluetooth/Nearby/เส้นทาง relay โดยอ้าง caseId และ revision UI แสดงจำนวนเครื่องที่ยืนยันรับ revision ปัจจุบัน ไม่เอา cloud synced มานับเป็นรับ SOS
2. เพิ่มรับเคส → กำลังช่วยเหลือ → แจ้งช่วยเหลือเสร็จ / ยกเลิกรับเคส โดยต้องเป็นกู้ภัยที่มีใบรับรองยังใช้ได้และเปิดปฏิบัติหน้าที่ สถานะส่งกลับผู้แจ้งได้แม้ออฟไลน์ พร้อมชื่อ เวลา และเปิดแชทหาผู้รับเคส
3. สถานะกู้ภัยไม่ปิด SOS ของผู้ประสบภัยอัตโนมัติ เจ้าตัวต้องกดหยุด SOS เอง มีหน้าต่างยืนยันก่อนแจ้งเสร็จ/ยกเลิกรับเคส
4. Receipt/ความคืบหน้าเก็บใน store sos_responses แยกเจ้าของและผู้ตอบ มี sequence ป้องกัน replay ถอยสถานะ มี ACK ของการตอบกลับ ค้างส่งแล้ว retry เมื่อพบเส้นทางอีกครั้ง รวมกรณี ACK ตกหล่น ล้างพร้อมลบบัญชีในเครื่อง และยกเลิกคิวตอบเคสที่รับรู้ว่าปิดแล้ว
5. คิวส่งหนึ่ง frame ต่อ endpoint ให้ control/SOS/ACK แซง bulk media ที่ยังรออยู่ รวม relay ที่มี bulk hint จำกัดจำนวน queued frames และแยกคิวแต่ละเครื่อง Frame ที่กำลังเขียนอยู่ไม่ถูกตัดกลาง เพราะจะทำไฟล์หรือ socket เสียหาย
6. กระจาย SOS ไปแต่ละลิงก์พร้อมกัน เครื่องตอบช้าหนึ่งเครื่องไม่กันอีกเครื่องจากการเริ่มรับ SOS
7. เพิ่มโปรไฟล์ → ตรวจความพร้อมออฟไลน์ ตรวจ local DB, transport/จำนวนลิงก์, GPS และการเปิดรับเบื้องหลัง โดยไม่เรียก HTTP/Auth/คลาวด์ มีทางไปเปิด/จับคู่อุปกรณ์
8. เตรียม release signing จาก android/key.properties และไฟล์ตัวอย่างที่ไม่มี secret AAB release จะถูกปฏิเสธถ้ายังไม่มี production key; APK ทดสอบยังใช้ signature เดิมเพื่ออัปเดตเครื่องเดิมได้ ไม่ได้สร้างหรือเผยแพร่ production key

## ขอบเขตของรุ่นนี้

Receipt เป็นคำยืนยันจากซอฟต์แวร์เครื่องปลายทางว่าได้รับและบันทึกแล้ว ไม่ใช่การกดรับเคสจากมนุษย์ ความคืบหน้าของแต่ละกู้ภัยเก็บสถานะล่าสุดในเครื่อง ไม่ได้มี audit timeline ทุก action หรือสำรอง store ใหม่นี้ขึ้นคลาวด์ในรุ่นนี้

สองฝั่งควรติดตั้งรุ่น 31 เพื่อใช้ receipt/รับเคสใหม่ รุ่นเก่ายังใช้แชท/SOS เดิมได้แต่จะไม่ตอบ receipt แบบใหม่ การทดสอบอัตโนมัติไม่ได้แทน field test วิทยุ/codec/Doze/แบตเตอรี่บนเครื่องจริง

ยังไม่เผยแพร่ขึ้น Store และไม่ได้เปลี่ยน live Supabase, package ID หรือกุญแจ APK ของเครื่องทดสอบ อ่าน docs/publishing-checklist-v31.md สำหรับรายการที่ต้องทำก่อนเผยแพร่สาธารณะ

ยังไม่ได้เพิ่ม durable store-carry-forward ของ private relay เมื่อเส้นทางปลายทางขาด, การเข้ารหัส local DB/cloud แบบ E2EE, หรือแผนที่ทั่วประเทศ จึงไม่อ้างความสามารถเหล่านี้
