# เทียบแอปกับคำแนะนำอาจารย์ — รุ่น 0.9.3+24

ตรวจวันที่ 1 พฤศจิกายน 2569 จากโค้ดและข้อความถอดเสียงของผู้ใช้

| ประเด็น | แอปก่อนรอบนี้ | การปรับ/ข้อจำกัด |
|---|---|---|
| ขอ SOS โดยไม่พิมพ์ | รุ่น 23 มีวงกดค้าง 3 วินาที บันทึกก่อน GPS | คงไว้ พร้อมตรวจ regression |
| SOS คนอื่นเห็นหน้าแรก | มีการ์ดสถานะล่าสุดด้านบน แตะเข้าห้องรวม | คงไว้ ไม่เพิ่ม toast ชั่วคราวแทนการ์ด |
| ระบุวิทยุที่ใช้งาน | ไม่แสดงในหน้าหลัก | เพิ่มจาก endpoint ที่เชื่อมจริง: Bluetooth โดยตรง/Nearby/ทั้งสอง ไม่กล่าวอ้างว่า Nearby ใช้ Wi-Fi เสมอ เพราะ SDK เลือกภายใน |

| แจ้งเตือนเร่งด่วน | SOS ใช้ช่องเดียวกับแชทและ envelope ID ใหม่ทุกครั้ง | เพิ่มช่อง SOS เสียง/สั่น มี ID คงที่ต่อเคส อัปเดตรายการเดิมไม่ส่งเสียงซ้ำ และยกเลิกเมื่อรับสถานะหยุด |
| UI แชทไม่เด้ง | เพิ่มแถบรับไฟล์ตามจำนวน ทำให้พื้นที่ยืดหด | พื้นที่สถานะขนาดคงที่ตามขนาดอักษร แสดงไฟล์แรกและจำนวน ปุ่มส่งไม่ถูกดันเมื่อเริ่ม/จบรับไฟล์ |

| ข้อความ/ภาพ/วิดีโอ | รองรับแชทรวม durable files คิว ACK/resume | ต้องพิสูจน์วิทยุเครื่องจริงรอบล่าสุด ไม่ใช้ผล mock แทน |

| กู้ภัย | สิทธิ์จากระบบและใบรับรอง โหมดน้ำเงิน ประวัติเคส | ไม่เพิ่มป้ายรับเคส/กำลังไปช่วยแบบไม่มี protocol ยืนยันกลับผู้ประสบภัย |
| สมาชิก/คลาวด์ | สมัคร/login/profile/delete/private storage/sync | ต้องทดสอบ session จริงและการซิงก์คิวบนสองเครื่อง |

## ยังไม่ควรกล่าวอ้างว่าผ่านแล้ว

1. ความเร็วค้นหา ระยะจริง เสียง/สั่นบนแต่ละยี่ห้อ รวม Doze และสิทธิ์แจ้งเตือนต้องทดสอบบนโทรศัพท์
2. แตะ SOS notification ทั้งตอนแอปเปิด พัก และเริ่มใหม่ รวมการเปลี่ยนบัญชี ต้องยืนยัน native E2E
3. การส่งข้อความ/รูป/วิดีโอสองทางระหว่าง OPPO/Galaxy และ relay ผ่านเครื่องที่สามต้องมีภาพ/วิดีโอผลจริง
4. เสียงขึ้นกับสิทธิ์ ระดับเสียง ช่องแจ้งเตือน และโหมดห้ามรบกวนของระบบ ไม่มีการข้าม DND
5. Force-stop/reboot ต้องเปิดแอปใหม่; การติดตั้ง foreground service ไม่ใช่การรับประกันว่า Android จะไม่ปิด process
6. ใบรับรองกู้ภัยต้องรับออนไลน์ครั้งแรกและต่ออายุภายใน 30 วัน การถอนสิทธิ์ไม่ถึงเครื่องที่ตัดขาดทันที
7. GPS ไม่รับประกันความคลาดเคลื่อนศูนย์ แผนที่ติดตั้งเฉพาะปทุมธานี ไฟล์จากคลาวด์ต้องโหลดครบก่อนเปิดออฟไลน์

## ข้อเสนอที่ยังไม่ได้เพิ่ม

- พูดแทนพิมพ์: เป็นข้อเสนอในบทสนทนา ไม่ใช่ข้อบังคับหลัก ยังไม่เพิ่ม recognizer ที่ต้องพึ่ง Internet แล้วเรียกว่าออฟไลน์
- รับเคสพร้อมแจ้งกำลังเดินทาง/ช่วยแล้ว: ควรทำเมื่อมี state/ACK/ประวัติและการยกเลิกที่สื่อสารกลับจริง ปัจจุบันใช้แชทสื่อสาร ไม่แสดงสถานะรับช่วยโดยสมมติ
- บีบอัดวิดีโอ: ต้องวัดเวลาและคุณภาพจริงก่อนเลือกเพิ่ม pipeline ไม่ได้อ้างว่าแก้ความเร็ววิทยุด้วย UI

ไม่มีการแก้ schema หรือสิทธิ์ Supabase ในรอบนี้ ไม่มีการลบข้อมูลผู้ใช้ ไม่ติดตั้งบนโทรศัพท์โดยอัตโนมัติ
