# SOSBROO 0.10.6+37

## สถานะอินเทอร์เน็ตในห้องแชท

สาเหตุเดิม: header ใช้เงื่อนไขสมาชิก + ผู้ติดต่อมี cloud user ID + อินเทอร์เน็ตพร้อม ทำให้ผู้ติดต่อจาก Nearby ที่ยังไม่มี cloud binding แสดงออฟไลน์แม้เครื่องมีอินเทอร์เน็ต

เปลี่ยน header ให้อ้างอิงอินเทอร์เน็ตของเครื่องที่กำลังเปิดแอป โดยไม่ขึ้นกับบัญชี/เส้นทางส่งของผู้ติดต่อ ป้ายนี้ไม่ได้รายงาน presence ของอีกฝ่าย ตรวจใหม่เมื่อเปิดห้อง ฟังการเปลี่ยนเครือข่าย และตรวจซ้ำทุก 15 วินาทีระหว่างบริการทำงาน Wi-Fi ที่ไม่มีทางออกอินเทอร์เน็ตยังเป็นออฟไลน์

NetworkService ตรวจ HTTPS ของ Supabase ก่อน หากไม่สำเร็จตรวจ HTTPS generate_204 ของ connectivitycheck.gstatic.com แบบไม่ตาม redirect และต้องได้ 204 พร้อม body ว่าง จึงไม่เอาหน้า captive portal มาเป็นหลักฐานว่าออนไลน์ ส่ง apikey เฉพาะโฮสต์ Supabase ไม่มีการส่งข้อมูลแชทไปยัง endpoint ตรวจอินเทอร์เน็ต หากเครือข่ายเปลี่ยนระหว่าง probe จะตรวจใหม่ก่อนเผยแพร่ผล และปิดบริการระหว่าง probe ได้โดยไม่เขียน notifier ที่ dispose แล้ว สถานะออนไลน์ไม่ได้รับรองว่าบริการคลาวด์ทุกบริการพร้อมใช้งาน งานคลาวด์ที่ล้มเหลวยังอยู่ในคิวเดิม

## เมนูข้อความเดียวกันทั้งออนไลน์และออฟไลน์

แตะปุ่มจุดสามจุดในข้อความ หรือกดค้างที่กล่องข้อความ:

- ตอบกลับ: อ้างอิง ID ข้อความเดิม
- แก้ไขข้อความ: ใช้ได้กับข้อความตัวอักษรที่ส่งเองและยังไม่ยกเลิก ส่งคำสั่งแก้ไขผ่าน durable queue เดิม
- ยกเลิกส่งข้อความ: ยืนยันก่อนนำเนื้อหาที่ส่งเองออกจากการแสดงผลทั้งสองฝั่ง ยังคงมีข้อความว่าได้ยกเลิกแล้ว หยุดคิวต้นฉบับ/ไฟล์ที่กำลังส่ง คำสั่งถูกเก็บไว้เมื่อยังติดต่ออีกฝ่ายไม่ได้
- ลบเฉพาะเครื่องนี้: ลบการแสดงผลข้อความที่รับหรือส่ง รวมกล่องยกเลิกแล้ว ไม่แก้ประวัติอีกฝ่าย เก็บ visibility tombstone แยกตามเจ้าของบัญชี ไม่ลบ durable queue จึงไม่ทำให้ข้อความที่ผู้ส่งยังต้องการส่งหายจากคิว และไม่กลับมาแสดงเมื่อโหลดแชทจากคลาวด์ซ้ำ

การลบเฉพาะเครื่องเป็นการซ่อนจากประวัติในแอป ไม่ใช่การล้างไฟล์อย่างถาวรจากอุปกรณ์ การแก้ไข/ยกเลิกจะถึงอีกฝ่ายเมื่อเชื่อมต่อด้วยอินเทอร์เน็ตหรือวิทยุออฟไลน์ได้ ทั้งสองฝั่งควรใช้รุ่นปัจจุบันเพื่อให้แสดงคำสั่งตรงกัน รูป/วิดีโอ/ตำแหน่งยังส่งผ่าน offline radio และคิวคลาวด์เดิม ไม่มีการเพิ่มเงื่อนไขให้ฟังก์ชันแชทต้องออนไลน์
