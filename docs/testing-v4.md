# ทดสอบ Offgrid SOS รุ่น 0.2.0+4

> รุ่นปัจจุบัน **0.3.0+5** เพิ่มกล้องและไฟล์ออฟไลน์ ดู [คู่มือรุ่น 5](testing-v5.md)
> ข้อความที่ระบุว่ารับส่งได้เฉพาะ text/SOS ด้านล่างเป็นข้อจำกัดของรุ่น 4

รุ่นนี้แก้ปัญหาจากภาพทดสอบ Galaxy และ Y33s วันที่ 18 ตุลาคม 2026
ต้องติดตั้ง APK รุ่นเดียวกันทั้งคู่ เนื่องจากเพิ่ม handshake ตัวตนผู้ใช้ รหัสข้อความและ acknowledgment
ไม่ควรใช้ v3 กับ v4 ปนกันเพื่อทดสอบแชท

## สิ่งที่เปลี่ยน

| ปัญหา | การแก้ในรุ่น 4 | หลักฐานก่อนส่ง APK |
|---|---|---|
| ออกจากแอปแล้วไม่มีแจ้งเตือน | Android notification channels, ขอ POST_NOTIFICATIONS บน Android 13+, บริการ foreground และ cached Flutter engine, รับข้อความ Cloud แยกจากหน้าสนทนา | ทดสอบเรียกแพลตฟอร์ม/กดระงับเมื่อเปิดห้องอยู่ และบิลด์ native สำเร็จ; ยังต้องทดสอบอุปกรณ์จริง |
| หน้า Nearby มีพื้นและตัวอักษรผิดเมื่อเปิดจาก SOS | หน้า Nearby มี Scaffold/Material ของตัวเอง ใช้สีตามธีมและรองรับตัวอักษรใหญ่ | widget tests และภาพตัวอย่างทั้งสองโหมด |
| พิกัด SOS กดไม่ได้ | ปุ่มเปิดแผนที่บน SOS ปัจจุบัน/ประวัติ/เคสที่รับ เปิด geo URI แล้ว fallback ไป HTTPS | ทดสอบพิกัดถูกต้อง/ไม่ถูกต้อง/การ fallback และปุ่มเปิดใช้งานได้ |
| แชทออฟไลน์แสดง SocketException | แชท Nearby ในแท็บแชท; ห้องสมาชิกเปลี่ยนไปใช้คู่ Nearby เมื่อออฟไลน์หรือ cloud ใช้ไม่ได้, เก็บข้อความรอส่ง | ทดสอบคิวเมื่อหลุดและส่งตามหลังจับคู่ |
| ปิดวิทยุ Wi-Fi แล้วส่งไม่ได้ | เพิ่ม secure Bluetooth RFCOMM สำหรับโทรศัพท์ที่จับคู่ในระบบแล้ว ไม่พึ่ง Wi-Fi | native code บิลด์ผ่าน; การเชื่อมวิทยุจริงยังต้องทดสอบสองเครื่อง |
| ข้อความ Nearby อยู่ผิดหน้า | นำ composer/feed ข้อความส่วนตัวออกจาก Nearby; เปิดห้องจากเครื่องที่เชื่อมต่อหรือแท็บแชท เก็บประวัติใน Sembast | widget tests ของการรับข้อความและกดส่งข้อความค้าง |
| อีกฝั่งหยุดแล้วยังค้างในรายการ | ส่ง goodbye ก่อนหยุด ล้าง peer/identity และ heartbeat ตรวจการหายเงียบ | ทดสอบจำลองหยุดหนึ่งฝั่งแล้วอีกฝั่งไม่มี peer ค้าง |
| ยกเลิก SOS ตอนหลุด | เก็บ revision ในเหตุและส่งประวัติสถานะรวมการยกเลิกเมื่อเชื่อมใหม่; ปฏิเสธ revision เก่า | ทดสอบส่งยกเลิกตามหลัง reconnect และสถานะอยู่หลังเปิดใหม่ |
| แชทส่วนตัวกระจายไป peer อื่น | ส่งตรงตาม identity ของลิงก์ที่จับคู่ ไม่ relay direct/case_chat; ตรวจ target และผู้ส่งก่อนบันทึก/รับ ack | ทดสอบจำลองสามเครื่องและการปลอม ack จากอีก peer |
| ช่องรหัสผ่านก่อนลบบัญชีไม่ถูกตรวจ | ตรวจรหัสผ่านด้วย signInWithPassword ก่อนเรียก delete-account | ตรวจเส้นทางโค้ด; ยังไม่ลบบัญชีจริง/ตรวจ Edge Function ในเซิร์ฟเวอร์ |
| ธีม/โลโก้ไม่ตรงความต้องการ | ธีมเหลือง/ดำและครีม/เหลือง โลโก้ป้ายเตือนพร้อมคำว่า SOS และไอคอนแจ้งเตือนสีขาว | ภาพ preview, ไอคอนทุก density, adaptive/monochrome, release build |

## ขอบเขตการแจ้งเตือน

บริการเริ่มหลังเข้าสู่หน้าหลักและเปิดได้ที่โปรไฟล์ มีแถบ **Offgrid SOS กำลังรับข้อความ**
รับได้ขณะกด Home หรือออกจาก Activity ตราบที่บริการและโปรเซสยังทำงานอยู่
แชทออนไลน์ใช้ Supabase Realtime พร้อมอินเทอร์เน็ต ส่วนแชท Nearby/Bluetooth ต้องมีลิงก์ที่เชื่อมต่ออยู่
แตะการแจ้งเตือนเพื่อเปิดแอป แล้วเปิดแท็บแชท

หากแอปถูก Force stop, เครื่องรีบูต หรือระบบผู้ผลิตฆ่าโปรเซส จะไม่สามารถรับต่อได้จนเปิดแอปอีกครั้ง
รุ่นนี้ยังไม่มี FCM push/ระบบเซิร์ฟเวอร์ที่ปลุกโปรเซสใหม่ และยังไม่อ้างว่าทดสอบการจอดับบนสองเครื่องจริงผ่านแล้ว
Vivo และ Samsung อาจมีการตั้งค่าประหยัดแบตเตอรี่/ทำงานเบื้องหลังเพิ่มเติม ต้องบันทึกผลจากเครื่องจริง

## เตรียมทดสอบ

1. อัปเดตทั้ง Galaxy และ Y33s เป็น 0.2.0 รุ่น 4 โดยใช้ APK เดียวกัน ไม่ถอนแอปเพื่อล้างข้อมูล
2. อนุญาตแจ้งเตือน แล้วดูโปรไฟล์ว่าเปิดการแจ้งเตือนและรับข้อความเบื้องหลังอยู่
3. ใช้ชื่อทดสอบที่แยกกันได้ เช่น Galaxy-Test และ Vivo-Test
4. เปิดตำแหน่ง Bluetooth และ Wi-Fi สำหรับชุด Nearby แรก โดยปิด mobile data และไม่ต่ออินเทอร์เน็ต
5. เริ่มค้นหาทั้งคู่ ให้เครื่องเดียวกดเชื่อม และตรวจรหัสจับคู่ให้ตรงกัน

## ชุด A: Nearby โดยไม่มีอินเทอร์เน็ต

- แตะเครื่องที่เชื่อมต่อเพื่อเปิดห้อง หรือไปแท็บแชท → แชท Nearby
- A ส่ง A01, B ส่ง B01; ต้องเห็นประวัติถูกคู่และสถานะรับถึงเครื่องแล้ว
- ปิดเปิดห้องและแอป; ประวัติยังอยู่ (ต้องจับคู่ใหม่หากโปรเซสถูกปิด)
- ขณะดูห้องอยู่ การรับข้อความห้องนั้นไม่ควรทำให้แจ้งเตือนซ้ำโดยไม่จำเป็น
- ไปหน้าหลักแล้วส่งข้อความจากอีกฝั่ง ดู badge ที่แท็บแชท

## ชุด B: ปิด Wi-Fi ทั้งสองเครื่อง

1. เข้า Android Settings → Bluetooth จับคู่โทรศัพท์สองเครื่องก่อน (ครั้งแรก)
2. ปิด Wi-Fi และ mobile data; เปิด Bluetooth ไว้
3. ใน Offgrid SOS ทั้งคู่ ไป Nearby → **ใช้ Bluetooth เมื่อปิด Wi-Fi**
4. ทั้งคู่เปิดรับแล้ว ให้ A เลือกชื่อ B จากรายชื่อที่จับคู่ เพียงฝั่งเดียว
5. B ปิดแผงเลือกได้และยังเปิดรับอยู่ รอชื่อคู่แสดงเชื่อมต่อแล้ว
6. ไปแท็บแชท ส่ง BTOFF01 ไปกลับ ตรวจว่าไม่มีการเรียก cloud เพื่อส่งข้อความชุดนี้

หากไม่มีชื่ออีกเครื่อง ให้กลับไปจับคู่ใน Settings; หากเชื่อมไม่ได้ ตรวจว่าเปิดรับ Bluetooth ในแอปทั้งคู่
เส้นทางนี้ส่งข้อความ/สถานะ SOS ไม่ใช่การส่งไฟล์แนบผ่าน Bluetooth

## ชุด C: การแจ้งเตือนจริง

ทดสอบทั้งผ่าน Nearby/Bluetooth และผ่านแชทสมาชิกออนไลน์ โดยไม่ใช้ข้อความจริงส่วนตัวในชุดทดสอบ

| กรณี | ขั้นตอน | เกณฑ์ผ่าน | ผลจริง |
|---|---|---|---|
| Home | A กด Home, B ส่ง C01 | A มี notification และแตะเปิดแอปได้ | รอทดสอบ |
| จอดับ | A ปิดหน้าจอ 30 วินาที, B ส่ง C02 | เห็นแจ้งเตือนเมื่อเปิดหน้าจอ/ได้เสียงตามการตั้งค่า | รอทดสอบ |
| ปัด Activity ออกจากหน้าล่าสุด | ยืนยันว่าบริการยังมีแถบสถานะ, B ส่ง C03 | ยังรับและแจ้งเตือนได้ถ้าระบบไม่ฆ่าโปรเซส | รอทดสอบ |
| ปิดสิทธิ์แจ้งเตือน | ปิดสิทธิ์ใน Settings แล้วส่ง C04 | ไม่มี notification, ข้อความยังถูกเก็บเมื่อบริการรับได้, หน้าโปรไฟล์บอกว่าปิด | รอทดสอบ |
| Force stop | บังคับหยุดใน Settings | บริการหยุด ต้องเปิดแอปใหม่ ไม่ถือเป็นกรณีที่รองรับการรับต่อ | ข้อจำกัด Android |

อย่าใช้เพียงการมองเห็น notification สรุปว่าทุกกรณีผ่าน ต้องเปิดห้องดูข้อความจริงและตรวจไม่ซ้ำด้วย

## ชุด D: SOS/พิกัด/หยุด

- A ส่ง SOS มีข้อความ TEST-SOS พร้อมพิกัด; A และ B ต้องกดเปิดตำแหน่งได้
- พิกัดไม่มี/ไม่ถูกต้องจะไม่เปิดแผนที่ผิดตำแหน่ง; พิกัดเก่าแสดงเวลาและป้ายกำกับ
- หยุด SOS ขณะเชื่อมต่อ เคสต้องเปลี่ยนเป็น inactive ฝั่ง B
- ทำให้หลุด แล้ว A หยุด SOS จากนั้นจับคู่ใหม่ เคสฝั่ง B ต้องไม่กลับ active
- ส่งข้อมูล active รุ่นเก่าซ้ำในการทดสอบโปรโตคอล สถานะยกเลิกต้องไม่ถูกย้อนกลับ
- สำหรับศูนย์ช่วยเหลือและแชทตามเคส B ต้องเป็นบัญชี rescuer/admin ที่อนุมัติแล้ว

## ชุด E: หยุดการเชื่อมต่อ

- A กดหยุด Nearby/Bluetooth; B ต้องไม่มีเครื่อง A แสดงว่าเชื่อมต่อหรือพร้อมจับคู่ค้าง
- B ยังเปิดค้นหาเครื่องอื่นต่อได้ ไม่จำเป็นต้องหยุดการค้นหาทั้งเครื่อง
- ห้องสนทนายังคงอยู่ มีสถานะรอเชื่อมต่อ และบันทึกข้อความค้างไว้ได้
- จับคู่ใหม่แล้วข้อความค้างต้องส่งตามโดยไม่สร้างข้อความซ้ำ
- ปิด Bluetooth/ออกนอกระยะ: ใช้ callback ของระบบและ heartbeat เมื่อแอปยังทำงาน; ขณะระบบพัก CPU อาจตรวจพบช้ากว่าเวลาปกติ
