# 0.9.4+25 — SOS เก่าไม่ใช่ SOS ที่ติดต่อได้ปัจจุบัน

## อาการและสาเหตุจากโค้ด

เคส Chiti วันที่ 30 แสดงบนหน้าแรกและศูนย์กู้ภัยแม้ connected=0
_loadSession โหลดสถานะ SOS จาก nearby_sos_states มาใส่ inbox และ UI เดิมกรองเพียง active=true ไม่ตรวจเส้นทางปัจจุบัน จึงใช้ประวัติที่ยังไม่มีข้อมูลปิดเคสเป็นหลักฐานว่าเป็นคนใกล้เคียง
ยังไม่มีหลักฐานจากภาพว่า Supabase ส่งเคส Chiti มาใหม่ การตรวจ sync_service พบการซิงก์ SOS ของเจ้าของบัญชี ไม่ควรสรุปว่า cloud กระจาย SOS นี้โดยไม่มี runtime logs

## การแก้

- รวมตัวกรอง currentSosCases ใน mesh: สถานะล่าสุดยัง active และมี direct peer ที่ connected หรือ relay route ยังไม่หมดอายุและตัวกลางยัง connected
- หน้าแรก/Nearby/Rescue ใช้ตัวกรองเดียวกัน ไม่มีเส้นทางจะไม่อยู่ในรายการปัจจุบัน
- เปลี่ยนชื่อรายการเป็น SOS ที่ติดต่อได้ ไม่กล่าวอ้างระยะทาง GPS จากการรับแพ็กเก็ตหรือการเชื่อมต่อ relay
- เก็บประวัติเดิมทั้งหมด และใช้ข้อความ สถานะที่ได้รับล่าสุด: เปิด SOS · ยังไม่ยืนยันปัจจุบัน แทนการกล่าวอ้างว่าคนเดิมกำลังขออยู่ตอนนี้
- ไม่ลบเคสหรือปิด SOS ของผู้อื่นอัตโนมัติ และไม่ใช้วันเก่าเป็นหลักฐานว่าปลอดภัยแล้ว
- แก้ ID แจ้งเตือนที่รอบก่อนเปลี่ยนผิดจุด: แชทใช้ message ID เดิม, SOS ใช้ origin+caseId เดียวกับตอนยกเลิกแจ้งเตือน

## Regression

เพิ่ม current_sos_cases_test: เคสเก่าบันทึกใน DB → เปิด/initialize ซ้ำ → ไม่ปรากฏใน current; direct connected → ปรากฏ; disconnect → หาย; relay valid → ปรากฏ; route expired → หาย; สถานะหยุดล่าสุด → หาย โดยประวัติใน DB ยังอยู่
ปรับ fixture UI ของเคส Victim ให้มี endpoint เชื่อมต่อจริง

เมื่ออุปกรณ์ต้นทางกลับมาเชื่อมต่อ เคสที่ยังเปิดอาจกลับมาแสดงได้ตามข้อมูลล่าสุด ไม่ใช่การอ้างว่าการรับผ่าน relay บอกระยะห่างจริงของบุคคล
ยังต้องทดสอบบนเครื่องจริงเมื่อสลับอินเทอร์เน็ต/เปิดแอปใหม่และตัดวิทยุ
