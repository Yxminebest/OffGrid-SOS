# รุ่น 0.9.8+29 — แชทและวิดีโอ

วันที่ 2 พฤศจิกายน 2569

## การแก้ไข

- ลบ subtitle “อนุมัติสิทธิ์แล้ว • ดูประวัติการตรวจสอบ” สำหรับสมาชิกที่ตรวจสิทธิ์กู้ภัยแล้ว โดยเมนูประวัติยังเปิดได้
- เปลี่ยนสถานะหัวห้องเป็นช่องทางที่เครื่องพร้อมส่ง: รอเชื่อมต่อ / Nearby เชื่อมต่อแล้ว / ส่งผ่านอินเทอร์เน็ต / Nearby และอินเทอร์เน็ตพร้อม สถานะนี้ไม่ใช่การตรวจออนไลน์ของผู้รับ
- แสดงไอคอนโล่สีน้ำเงินแยกต่างหาก เมื่อมีหลักฐานสิทธิ์และสถานะปฏิบัติหน้าที่กู้ภัยปัจจุบัน
- เปิดวิดีโอแล้วเริ่มเล่นหลัง initialize ใช้พื้นที่วิดีโอที่มีขอบเขตเพื่อให้ปุ่มควบคุมและแถบเลื่อนอยู่ในจอ รวมเวลาเล่น/ความยาว และหยุดเมื่อแอปเข้าเบื้องหลัง มี timeout/error สำหรับเปิดไฟล์ไม่สำเร็จ
- Progress ของไฟล์ไม่เรียกซิงก์ทั้ง inbox ทุกแพ็กเก็ตอีกต่อไป ตัวปลุกซิงก์ติดตาม topology/ตัวตนผู้รับแทน และจำกัดการแจ้ง progress หน้าจอทุก 200 ms รวมการเปลี่ยน DB ภายใน 40 ms ก่อนอ่าน inbox ใหม่
- คำนวณ ECDH ครั้งเดียวต่อ exchange key ต่อ session เก็บสูงสุด 128 รายการและล้างเมื่อ initialize session ใหม่ AES-GCM ยังใช้ nonce ใหม่และตรวจ authentication ทุกข้อความ ไม่เปลี่ยนหลักฐานตรวจตัวตน/ลายเซ็น
- ไม่ลบแล้วสร้างรายการสนทนาทั้งชุดเมื่อข้อมูลเหมือนเดิม ไม่เขียนข้อความคลาวด์เดิมซ้ำ และตัด HTTP refresh ซ้ำท้าย Realtime batch
- ดาวน์โหลด HTTP ไม่ flush ไฟล์ทุก network chunk ยังปิดไฟล์/ตรวจขนาดก่อน rename และไม่เปิด partial file
- วิดีโอและรูปของสมาชิกที่รู้รหัสบัญชี เมื่ออินเทอร์เน็ตพร้อม ให้คลาวด์เริ่มก่อน สูงสุด 8 วินาทีก่อน Nearby fallback และ fallback ได้ทันทีเมื่อออฟไลน์ คิววิทยุยังรอ ACK ของผู้รับ แม้คลาวด์บันทึกสำเร็จแล้ว ข้อความ/SOS ไม่รอช่วงนี้
- ไม่แสดง error/progress การส่งวิทยุเก่าทับข้อความที่ซิงก์แล้ว แต่ synced ไม่ถือว่าได้รับ ACK จากผู้รับ

## การตรวจสอบ

- ชุดทดสอบ Flutter ทั้งหมด 192 เคสผ่าน (`build/tests-v29.log`)
- เคสเพิ่มครอบคลุม auto-play วิดีโอแนวตั้ง ปุ่มไม่หลุดจอ pause เบื้องหลัง/dispose, สถานะทั้ง 4 ช่องทาง, 200 progress notifications ไม่ทำให้ซิงก์ inbox ซ้ำ, cloud-first media และ fallback ให้ผู้รับออฟไลน์แม้ server บันทึกแล้ว, nonce ไม่ซ้ำและเปลี่ยนบัญชีแล้วไม่ใช้ shared key เดิม
- ชุดเดิมยังตรวจไฟล์ผ่าน 3 nodes การส่งต่อเมื่อเชื่อมกลับ hash corruption แยกบัญชี และเก็บคิวออฟไลน์
- Static analysis: ดู `build/analyze-v29.log`
- Release APK: `build/app/outputs/flutter-apk/Offgrid-SOS-v29-fast-chat-video.apk` ผล build ใน `build/apk-v29.log`

## ขอบเขตที่ต้องตรวจบนเครื่องจริง

ยังไม่มีผลทดสอบ codec/ความเร็ว/หน่วยความจำบน OPPO และ Galaxy หลังเปลี่ยนรุ่นนี้ การทดสอบ player ใช้ fake platform จึงยืนยัน flow และ layout ได้ แต่ไม่ยืนยันว่า codec ของวิดีโอจริงรองรับบนฮาร์ดแวร์เก่าทุกแบบ ต้องลองคลิปจริงทั้งสองเครื่อง รวมเปิดจอหลังล็อกและสลับอินเทอร์เน็ต ไม่มีการเปลี่ยน schema หรือข้อมูลผู้ใช้ใน Supabase ในรุ่นนี้
