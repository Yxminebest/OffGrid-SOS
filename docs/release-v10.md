## สิ่งที่แก้จากภาพทดสอบสองเครื่อง

- ปุ่มพิกัดใน SOS, ศูนย์กู้ภัย และแชท เปิดหน้าแผนที่ภายในแอปโดยตรง แทนแผงพิกัดซ้อนและการส่งต่อไป Google Maps
- แผนที่มีหมุดพิกัดที่บันทึกไว้ เลื่อน/ซูม กลับไปยังหมุด คัดลอกพิกัด และแสดงที่มาของ OpenStreetMap
- แสดงข้อความเมื่อโหลดภาพแผนที่ไม่สำเร็จ พร้อมลองใหม่ โดยยังอ่านและคัดลอกพิกัดได้
- เวลาในรายละเอียด SOS ที่รับผ่าน Nearby แสดงเป็นเวลาท้องถิ่น แทน ISO UTC
- หน้าอนุมัติหน่วยกู้ภัยซ่อนฟอร์มส่งคำขอซ้ำเมื่อสถานะ approved
- ข้อความรูป/วิดีโอ Nearby แสดงชื่อชนิดสื่อสั้น ๆ แทนชื่อไฟล์ UUID ยาว ชื่อเต็มยังดูได้ด้วยการกดค้าง และอยู่ในหน้าเปิดสื่อ
- เมนู + ในแชท Nearby ส่งตำแหน่งจาก GPS ได้ทั้งแชททั่วไปและแชทเคส SOS มีหน้าตรวจพิกัด/เวลาบันทึกก่อนยืนยัน และเตือนเมื่อใช้ last-known location พิกัดส่งผ่านซองข้อความส่วนตัวที่เข้ารหัส เก็บในคิวเดิมและรับ ACK ปลายทาง
- แสดงพิกัดที่แชร์เป็นการ์ดพร้อมปุ่มเปิดแผนที่ภายในแอป ฝั่งที่ยังใช้แอปเก่าอ่านพิกัดได้จากข้อความ
- ตรวจผลคำขอสิทธิ์เมื่อเปิด/กลับเข้าแอป เมื่อกลับมาออนไลน์ และทุก 30 วินาทีขณะบริการทำงานและออนไลน์ แจ้งผลอนุมัติ/ไม่อนุมัติครั้งเดียวต่อผลตรวจสอบ พร้อมปรับ role ในหน้าหลักโดยไม่ต้องออกจากระบบ
- เมนูโปรไฟล์: สถานะและประวัติคำขอสิทธิ์กู้ภัย / ประวัติเคส SOS ที่ได้รับ
- เมนูศูนย์กู้ภัย: ประวัติเคส SOS ที่ได้รับ / ประวัติการขอสิทธิ์กู้ภัย รวมชื่อหน่วยงาน วันส่งคำขอ วันตรวจสอบ และเหตุผลไม่อนุมัติถ้ามี
- ประวัติแยกตามบัญชีและอ่านจาก local DB ขณะออฟไลน์ได้ เคสที่ผู้แจ้งหยุด SOS ยังคงอยู่และเปิดดูบทสนทนาของเคสได้ ประวัติไม่ได้ยืนยันว่าช่วยเหลือสำเร็จ

## ขอบเขตการแจ้งผลอนุมัติ

เป็นการตรวจสถานะจาก Supabase และแจ้งเตือนในแอป/ผ่านระบบ Android เมื่อกระบวนการของแอปยังทำงาน ต้องมีอินเทอร์เน็ตเพื่อรับผลใหม่ หากถูก force-stop หรือระบบปิดกระบวนการ จะตรวจเมื่อเปิดใหม่ ไม่ใช่ FCM push ที่ปลุกแอปจากสถานะปิดทั้งหมด และไม่ขอสิทธิ์กู้ภัยจากข้อมูลประวัติ: role ปัจจุบันยังอ่านจากเซิร์ฟเวอร์

ใช้ตารางและ RLS เดิม ไม่แก้ schema หรือข้อมูลผู้ใช้บนเซิร์ฟเวอร์ ตรวจจริงแล้วว่าสิทธิ์ authenticated ที่ไม่ใช่เจ้าของอ่านคำขอคนอื่นไม่ได้ การอ่านประวัติใช้ user_id ของ session และแบ่งหน้าละ 200 รายการ ไม่ดึง document_path หรือรหัสเจ้าหน้าที่มาเก็บในแคชประวัติ

## ขอบเขตแผนที่

ตำแหน่งเป็นพิกัดที่บันทึกหรือได้รับจากคู่สนทนา ไม่ใช่ live tracking หรือระบบนำทาง ภาพถนนโหลดจาก OpenStreetMap ผ่าน HTTPS โดยมี app user agent และ attribution ใช้แคชตาม HTTP headers ของ flutter_map ไม่มีการดาวน์โหลดพื้นที่ล่วงหน้าหรือ bulk download

เมื่อไม่มีอินเทอร์เน็ต พิกัดและหมุดยังใช้งานได้ แต่ภาพถนนที่ไม่เคยโหลดอาจไม่ปรากฏ แคชที่ระบบล้างไปแล้วไม่รับประกันว่าจะเปิดได้ จึงยังไม่ใช่แพ็กเกจแผนที่ถนนออฟไลน์ครบพื้นที่ ดู [ข้อจำกัดของแคช](https://docs.fleaflet.dev/layers/tile-layer/caching) และ [นโยบาย tile server](https://operations.osmfoundation.org/policies/tiles/)

## หลักฐานและการตรวจ

- ภาพจากผู้ใช้: ข้อความและรูปปรากฏทั้งสองเครื่อง มีสถานะรับถึงเครื่องแล้ว และมี SOS ในศูนย์กู้ภัย
- ภาพยังไม่เพียงพอที่จะยืนยันการส่งวิดีโอ การแจ้งเตือนเบื้องหลัง การซิงก์คลาวด์ หรือ multi-hop 3 เครื่อง
- `flutter analyze --no-pub`: ผ่าน ไม่มีปัญหา
- `flutter test --no-pub`: ผ่าน 103 เคส รวมเปิดหน้าแผนที่ในแอป หมุดตรงพิกัด คัดลอกพิกัด ซูม/กลับหมุด ลองใหม่หลัง tile error จอ 320×640 ที่ขยายตัวอักษร 1.8 เท่า การส่งตำแหน่งผ่านเครื่องตัวกลาง การแจ้งอนุมัติครั้งเดียวหลังเปิดใหม่ การไม่ใช้สิทธิ์เก่าที่ถูกถอน และการแยกแคชระหว่างบัญชี
- การทดสอบแผนที่อัตโนมัติใช้ tile provider จำลอง ไม่มีการร้องขอ public tiles ในชุดทดสอบ

## ทดสอบจริงหลังอัปเดต

1. กดพิกัดจาก SOS, รายละเอียดเคสกู้ภัย และข้อความตำแหน่ง ต้องเปิดหน้าแผนที่ในแอปและกดย้อนกลับได้
2. ออนไลน์: ภาพถนนและหมุดโหลดได้ เลื่อน/ซูม/กลับหมุด และคัดลอกพิกัดตรงกับต้นทาง
3. ออฟไลน์: อ่าน/คัดลอกพิกัดได้ ไม่มีแอปภายนอกเปิดขึ้น แสดงข้อความโหลดไม่สำเร็จเมื่อภาพถนนไม่มี แล้วลองใหม่เมื่อออนไลน์
4. บัญชีกู้ภัย approved: ไม่แสดงปุ่มส่งคำขอซ้ำ โหมดกู้ภัยยังเปิดปิดได้ตามเดิม
5. รูป Nearby ยังเปิดดูได้หลังย่อชื่อไฟล์ และเวลาของ SOS เป็นเวลาท้องถิ่น
6. แชท Nearby → + → ตำแหน่งของฉัน: ตรวจพิกัดแล้วส่ง ตรวจอีกเครื่องได้รับการ์ดและเปิดหมุดตรงกัน ทดสอบปิดอินเทอร์เน็ตแต่เปิดวิทยุ Bluetooth/Wi-Fi สำหรับ Nearby
7. ตัดการเชื่อมต่อ ส่งพิกัดแล้วให้ค้างส่ง จับคู่ใหม่ต้องส่งถึงและได้รับ ACK เปิดแอปใหม่ยังอ่านการ์ดได้
8. บัญชีที่กำลังรออนุมัติ: ให้ Admin อนุมัติ ขณะเครื่องผู้ขอออนไลน์และแอปทำงาน ต้องมีข้อความแจ้งผลและ role เปลี่ยนภายในรอบตรวจสอบ ไม่แจ้งซ้ำเมื่อรีเฟรชหรือเปิดใหม่
9. โปรไฟล์/ศูนย์กู้ภัย → ประวัติ: ตรวจชื่อหน่วยงาน ผลตรวจ วันเวลา และเคสที่หยุด SOS แล้ว เปิดออฟไลน์ต้องอ่านข้อมูลที่เคยโหลดไว้ได้
