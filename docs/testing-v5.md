# กล้องและไฟล์ออฟไลน์ — Offgrid SOS 0.3.0+5

> อัปเดตปัจจุบัน **0.3.1+6** แก้รูปเก่าจากคลาวด์ขณะ offline สถานะการส่ง และแผงพิกัด
> ดู [testing-v6.md](testing-v6.md); โปรโตคอลรับส่ง Nearby ของรุ่น 5 ยังใช้ต่อในรุ่น 6

รุ่น 5 เพิ่มถ่ายรูปจากกล้องในแชทออนไลน์และ Nearby
ห้อง Nearby ส่งข้อความ รูป และวิดีโอตรงถึงโทรศัพท์ที่จับคู่ผ่าน Nearby Connections
หรือ secure Bluetooth RFCOMM โดยไม่ต้องมี SIM data, Internet หรือ Wi-Fi hotspot
กรณีปิดวิทยุ Wi-Fi ต้องใช้ Bluetooth ที่เปิดและเชื่อมอยู่ทั้งสองฝั่ง
ไม่สามารถส่งถึงเครื่องที่ปิดวิทยุทั้งหมด/อยู่นอกระยะได้; แอปจะเก็บคิวไว้แทน

## ใช้งาน

1. อัปเดต **Galaxy และ vivo Y33s เป็นรุ่น 0.3.0 build 5 ทั้งคู่** ด้วย APK เดียวกัน
2. เปิด Nearby และจับคู่ตามขั้นตอนเดิม แล้วเข้าแท็บแชท → เลือกคู่สนทนา Nearby
3. กด **+ → ถ่ายรูป**, **รูปภาพจากเครื่อง** หรือ **วิดีโอจากเครื่อง**
4. หลังถ่าย/เลือก แอปคัดลอกไฟล์ไว้ในเครื่องและเริ่มส่งเมื่อมีลิงก์
5. ดูเปอร์เซ็นต์ระหว่างส่ง; คำว่า **รับถึงเครื่องแล้ว** แสดงเมื่อผู้รับบันทึกไฟล์ครบและตรวจ hash ผ่าน
6. แตะรูปเพื่อขยาย หรือกดเล่นวิดีโอในเครื่อง ดูได้แม้ไม่มีอินเทอร์เน็ต

แชท cloud ใช้เมนูแนบไฟล์ → ถ่ายรูปเช่นกัน หากจับคู่ Nearby กับสมาชิกคนนั้นแล้ว
ใช้ปุ่ม Bluetooth บนแถบด้านบนเพื่อเลือกส่งผ่าน Nearby โดยตรง
เมื่อ offline/cloud ใช้ไม่ได้และมีคู่เชื่อมอยู่ ห้องเดิมเปลี่ยนไป Nearby ตาม flow รุ่น 4
กรณียังไม่จับคู่ การบันทึกเข้า cloud queue ไม่ได้แปลว่าอีกเครื่องได้รับผ่าน Bluetooth แล้ว

## การเก็บและส่งไฟล์

- สูงสุด **25 MB ต่อไฟล์** สำหรับ Nearby/Bluetooth และรูปจากกล้อง
- รูปจากกล้อง/รูปที่เลือกใน Nearby ใช้ขนาดสูงสุด 1920 × 1920 และ quality 85 เพื่อลดเวลาโอน
- วิดีโอเลือกจากเครื่อง ไม่บีบอัดวิดีโออัตโนมัติ และยังไม่มีปุ่มบันทึกวิดีโอด้วยกล้อง
- แบ่งส่วนละ 12 KiB แปลง base64 ให้อยู่ภายใน transport frame 32 KiB
- ส่งทีละส่วน รอคำตอบหลังเขียนลงดิสก์ แล้วส่งส่วนถัดไป จำกัดหนึ่งไฟล์ส่งต่อ peer ในเวลาเดียวกัน
- มี SHA-256 ของไฟล์เต็ม ผู้รับไม่สร้างข้อความสำเร็จถ้าไฟล์ไม่ครบ/hash ไม่ตรง
- ข้อมูลไฟล์อยู่ใน private application support directory; DB เก็บ path/metadata ไม่มี base64 ของไฟล์เต็ม
- ไฟล์ค้างฝั่งผู้รับเก็บเป็น `.part`; เมื่อ reconnect หรือเปิดแอปและจับคู่ใหม่ จะตอบ offset ที่มีแล้วให้ส่งต่อ
- การ retry/รับซ้ำใช้ message ID เดิม จึงไม่สร้างข้อความรับซ้ำ
- การรับไฟล์และข้อความส่วนตัวส่งผ่านลิงก์ที่จับคู่เท่านั้น ยังไม่มี file/chat routing ผ่านตัวกลางหลายทอด
- Nearby history/ไฟล์ยังไม่ได้ sync ขึ้น Supabase; คิว cloud และคิว D2D ยังแยกกัน
- ต้องมีพื้นที่พอทั้งสองเครื่อง; ถ้าคัดลอกหรือเขียนไม่ได้จะแสดงข้อผิดพลาดและไม่ยืนยันรับสำเร็จ

Camera Activity อาจทำให้ Android ปิดแอปเมื่อหน่วยความจำน้อย จึงบันทึกบัญชี/ห้องก่อนเปิดกล้อง
และเรียก retrieveLostData เมื่อกลับเข้าหน้าหลัก ผลกู้คืนไม่ถูกส่งเข้าบัญชีอื่น
เมื่อส่งเข้าคิวแล้วไฟล์ถูกคัดลอกออกจาก camera cache; รูปในคิวจึงไม่หายเพราะลบ cache ของกล้อง
