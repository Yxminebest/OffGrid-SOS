# Release 0.9.7+28 — Chat routing and reconnection

## การแก้ไข

1. เก็บรหัสบัญชีคลาวด์ที่เคยตรวจใบรับรองแล้วแยกจากสิทธิ์วิทยุปัจจุบัน การเชื่อมใหม่ที่ยังตรวจใบรับรองไม่เสร็จไม่ล้างปลายทางคลาวด์ทิ้ง ไม่จับคู่ด้วยชื่อ และไม่ใช้ hello ที่ไม่ผ่านการตรวจเป็นหลักฐานบัญชี
2. ข้อความส่วนตัวทางวิทยุที่ผูกบัญชีต้องตรงกับผู้รับที่มีหลักฐานปัจจุบันก่อนส่งหรือ retry จึงไม่ส่งไปยังเครื่องที่อ้างชื่อเดียวกัน
3. ผู้ติดต่อสมาชิกที่ยังไม่มี room สามารถสร้างห้องออนไลน์และบันทึกข้อความได้ การส่งผ่านคลาวด์ใช้ message ID เดียวกับคิววิทยุ รวมรูป วิดีโอ และตำแหน่ง
4. ฟังสถานะอินเทอร์เน็ตเพื่อเริ่ม drain คิวทันที และดึง inbox/messages ผ่าน HTTP ทุก 15 วินาที รวมเมื่อกลับมาออนไลน์/เปิดจอ เพื่อสำรองกรณี Realtime หลุด ไม่มีการลบข้อความเก่าจาก partial snapshot
5. ตรวจ profiles ของบัญชีผู้ติดต่อเมื่อออนไลน์ ก่อนซิงก์/เปิดหน้ารายการ หากเซิร์ฟเวอร์ยืนยันว่าไม่มีบัญชีนั้น ซ่อนรายการและหยุดคิวที่เกี่ยวข้อง โดยแยกตามเจ้าของข้อมูล HTTP error/timeout/ออฟไลน์ไม่ถือว่าบัญชีถูกลบ
6. สำหรับแชท legacy ที่ไม่มีหลักฐานรหัสบัญชี จะไม่เดาจากชื่อ มีเมนูกดค้างรายการเพื่อซ่อนบทสนทนาในเครื่อง ข้อมูลเดิมยังเก็บไว้ และส่งข้อความใหม่แล้วแสดงห้องอีกครั้งได้
7. เพิ่ม CPU wake lock แบบมี timeout และต่ออายุระหว่างเปิดบริการรับข้อความ รวม Wi-Fi lock ของ Android และคืน lock เมื่อหยุดบริการ ต้องเปิดรับข้อความเบื้องหลังไว้ การทำงานส่วนนี้เพิ่มการใช้พลังงาน
8. เก็บ endpoint ที่ยังค้นพบหลังลิงก์หลุดเพื่อ retry เปิดค้นหาใหม่เมื่อกลับสู่แอป และกระตุ้นคิว/คลาวด์อีกครั้ง
9. สถานะ sent ของวิทยุเปลี่ยนเป็น “กำลังส่ง · รอผู้รับยืนยัน” เพื่อไม่อ้างว่าส่งถึงผู้รับแล้วก่อน ACK; synced ยังคงหมายถึงเซิร์ฟเวอร์บันทึกแล้ว

## ผลตรวจ

- `flutter analyze --no-pub`: ไม่มีปัญหา (`build/analyze-v28.log`)
- Android release APK ประกอบสำเร็จ รวม Kotlin wake/Wi-Fi lock (`build/apk-v28.log`) ตรวจ versionName 0.9.7 / versionCode 28
- ทดสอบทั้งหมดผ่าน 187 เคส: `build/tests-v28.log`
- มีเคสใหม่สำหรับตัวตนเดิมหลัง reconnect, ส่งออนไลน์โดยไม่มีเครื่อง Nearby, ยกเลิกคิวบัญชีที่ลบ, ไม่ซ่อนข้อมูลเมื่อ directory ล่ม, ซ่อน/เปิดแชท legacy, รูปและวิดีโอจาก offline queue ไปคลาวด์ด้วย ID/bytes เดิม, และเชื่อมกลับเครื่องที่ยังค้นพบ
- ตรวจ Supabase public endpoint จริง: `/auth/v1/health` HTTP 200 และ public key ของ `mesh-attestation` ตรง trust anchor ใน APK
- ครั้งนี้ไม่ได้เปลี่ยน schema/RLS/Edge Function บน Supabase และยังไม่ได้ทดสอบส่งด้วย session สมาชิกจริงบนโทรศัพท์สองเครื่องหลังติดตั้งรุ่น 28
- ต้องทดสอบจอดับ/เปิดใหม่ ส่งรูป/วิดีโอ/ตำแหน่งจริงทั้งออนไลน์และตัดอินเทอร์เน็ต รวมการลบบัญชีจากอีกเครื่องก่อนยืนยันผ่านภาคสนาม
- APK: `build/app/outputs/flutter-apk/Offgrid-SOS-v28-chat-recovery.apk`

## ขอบเขตของเบื้องหลัง

Wake lock ช่วยให้ CPU ทำงานเมื่อจอดับตาม Android foreground-service flow แต่ไม่รับประกันรอดจากการ force-stop/reboot หรือการจำกัดของผู้ผลิต อ้างอิง https://developer.android.com/develop/background-work/background-tasks/awake

สถานะสีแดง SOS และสีน้ำเงินกู้ภัยยังใช้สถานะปัจจุบัน/เส้นทางที่ติดต่อได้และใบรับรองกู้ภัยเดิม ไม่อ้างว่าผู้ติดต่อจากประวัติคลาวด์อยู่ในระยะวิทยุ
