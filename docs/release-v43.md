## ปิด SOS เมื่อช่วยเหลือเสร็จ

เดิม completed เป็นเพียงสถานะตอบกลับและไม่หยุด SOS รุ่นนี้:

1. ฝั่งกู้ภัยตรวจสิทธิ์/โหมดปฏิบัติงานและลำดับ accepted → helping → completed ตามเดิม แล้วบันทึกคำสั่ง completed ในเครื่องก่อนส่ง
2. ซ่อนเคสที่กู้ภัยยืนยัน completed แล้วจากรายการ SOS ที่กำลังทำงานในเครื่องกู้ภัย และโหลดสถานะนี้กลับได้หลังเปิดใหม่ โดยไม่ปลอมสถานะ SOS ที่ลงลายเซ็นของผู้ประสบภัย
3. เมื่อเครื่องผู้ประสบภัยรับคำยืนยัน ตรวจเส้นทางที่ยืนยันตัวตน ใบรับรองสิทธิ์กู้ภัย เจ้าของ record, caseOrigin, caseId, revision และ sequence ก่อนปิดเคสที่ตรงกันใน local DB
4. การปิดทำใน transaction แบบ idempotent ตั้ง isActive=false, endedAt และเพิ่ม revision เพียงครั้งเดียว พร้อมเข้าคิวซิงก์ sos_events สำหรับสมาชิก
5. เครื่องผู้แจ้งประกาศ SOS ปิดที่ลงลายเซ็นของตัวเองไปยังเพื่อนบ้าน/ตัวกลาง และตอบ ACK กลับ ไม่ต้องให้ผู้แจ้งกดหยุดเอง

ถ้าสัญญาณหลุด เครื่องปลายทางยังปิดพร้อมกันทันทีไม่ได้ คำยืนยันจะอยู่ในคิวและส่งซ้ำเมื่อเชื่อมต่อ การตอบซ้ำหลังปิดแล้วไม่เพิ่ม revision หรือเปิด SOS กลับ และการปิด/ประกาศซ้ำของเคสเก่าต้องไม่ล้างสถานะ SOS เคสใหม่

บันทึก response ก่อนปิด DB อาจถูกขัดจังหวะระหว่างสอง transaction จึงรองรับการรับ completed ID เดิมซ้ำและทำขั้นตอนปิดให้ครบก่อน ACK เทสจำลองช่องว่างนี้แล้ว บุคคลทั่วไปที่ไม่มีใบรับรองกู้ภัยไม่สามารถปิด SOS ด้วย progress ปลอมได้
