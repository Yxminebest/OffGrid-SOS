# ทดสอบรวมรุ่น 0.4.0+9

## สิ่งที่เพิ่ม

- แชทข้อความ รูป วิดีโอผ่านตัวกลางหลายทอด พร้อมเข้ารหัส payload ที่ส่งผ่านตัวกลาง
- เส้นทางค้นพบ/หมดอายุ/ถอนเมื่อเครื่องหลุด และคิวรอส่งใหม่โดยไม่สร้างข้อความซ้ำ
- สถานะ Rescue น้ำเงินบนเครื่องอื่น การประกาศซ้ำเมื่อเชื่อมใหม่ และปิดแล้วถอนสถานะ
- Nearby discovery ประกาศ SOS/Rescue ก่อนจับคู่; แตะรายการเพื่อจับคู่แล้วเข้าแชท
- แตะการ์ด SOS ใน Nearby/Rescue เข้าแชทโดยตรง มีปุ่มดูรายละเอียดและพิกัดแยกไว้
- สมาชิกสำรองประวัติ Nearby และสื่อขึ้น private cloud archive พร้อมปุ่มกู้คืน
- ตรวจการเข้าถึงคลาวด์จริง ไม่ตีความ Wi-Fi ออฟไลน์ว่าเป็นอินเทอร์เน็ต
- กล้องมี message ID เดิมเมื่อกู้คืน ป้องกันรูปซ้ำ และลบบัญชีแล้วล้างไฟล์ของบัญชีนั้น
- retry การสำรองมี backoff ตรวจตารางก่อนอัปโหลดไฟล์ และไม่อัปโหลดไฟล์เดิมซ้ำเพราะ metadata ล้มเหลว

## เตรียมครั้งเดียว

1. ติดตั้ง `Offgrid-SOS-v9-complete.apk` **ทั้งสองเครื่อง** แบบอัปเดตทับ เก็บข้อมูลเดิม ไม่ถอนแอป
2. เปิดสิทธิ์ Bluetooth/Nearby/ตำแหน่ง/กล้อง/แจ้งเตือน และบริการตำแหน่งตามที่ Android ขอ
3. เปิดรับข้อความเบื้องหลัง และตรวจว่าแถบบริการแสดงอยู่ก่อนทดสอบออกจากหน้าจอ
4. ทดสอบสมาชิกออนไลน์และกู้ภัยด้วยบัญชีที่ admin อนุมัติแล้ว; Guest ทดสอบ D2D ได้
5. ตั้งค่า cloud ตาม `backend-setup.md` ก่อนทดสอบสำรอง Nearby รุ่นใหม่
6. โหมดออฟไลน์: ปิด mobile data และตัดออกจาก Wi-Fi hotspot/AP แต่เปิดวิทยุ Wi-Fi/Bluetooth
   หากปิดวิทยุ Wi-Fi ทั้งหมด ให้จับคู่ Bluetooth ในตั้งค่าระบบก่อน แล้วใช้ปุ่ม Bluetooth โดยตรงในแอปทั้งคู่

## วิธีพิสูจน์หลายทอด

ต้องมี 3 โหนด เปิดแอปทั้งหมด จับคู่ A–B และ B–C เท่านั้น ไม่จับคู่ A–C
รายการ A ต้องแสดง C “ผ่านเครื่องตัวกลาง • 2 ทอด” ก่อนส่งข้อความ รูป และวิดีโอ
บันทึกหน้าจอ A/C และหน้าประวัติ B ซึ่งต้องไม่มีแชทส่วนตัว A–C
ทดสอบซ้ำโดยจัดระยะให้ A–C ติดต่อโดยตรงไม่ได้ แล้วตัด B เพื่อพิสูจน์ว่าลิงก์อาศัยตัวกลาง
เส้นทางจำกัด 6 ทอด อุปกรณ์ตัวกลางต้องเปิดและเชื่อมต่ออยู่ ไม่ใช่บริการส่งต่อหลังเครื่องถูกปิด

## ขอบเขตที่ต้องทราบระหว่างทดสอบ

- Wi-Fi/Bluetooth เป็นวิทยุที่ส่งข้อมูล ออฟไลน์ไม่ได้หมายถึงปิดวิทยุทุกตัว
- แผนที่ Google อาจต้องใช้ Internet/แผนที่ที่ดาวน์โหลดไว้ แต่พิกัดกับเวลาที่บันทึกอ่าน/คัดลอกในแอปได้เสมอ
- Archive ที่กู้คืนเป็นประวัติ ไม่ย้อนส่งข้อความของ identity เก่าหลังลงแอปใหม่ และไม่เปลี่ยน pending เป็นรับถึงเครื่อง
- กุญแจเส้นทางใช้ trust on first contact; การจับคู่โดยตรงยืนยันลิงก์ ส่วนใบประกาศตัวเองไม่ได้รับรอง role บนเซิร์ฟเวอร์แบบ PKI
- การติดตั้งใหม่ที่ล้างกุญแจ/identity ต้องสร้างคู่เชื่อมต่อใหม่ การสำรองประวัติไม่ได้สำรอง private key
- Foreground service รับเมื่อ process ยังทำงาน ไม่ใช่ FCM ที่ปลุก process ใหม่ หลัง force-stop/reboot ต้องเปิดแอปใหม่
- Discovery เปลี่ยนสถานะตามรอบค้นหาของ Android ไม่รับประกันจำนวนวินาทีจนกว่าจะวัดเครื่องจริง
